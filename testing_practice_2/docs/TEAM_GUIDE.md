# Командная инструкция: практическая работа № 2

## Роли и обмен модулями

| Участник | Автор модуля | Тестирует модуль |
|---|---|---|
| Максим | `calculator.py` | `number_checks.py` Кати |
| Витя | `text_tools.py` | `calculator.py` Максима |
| Артем | `list_tools.py` | `text_tools.py` Вити |
| Катя | `number_checks.py` | `list_tools.py` Артема |

Каждый участник разрабатывает один модуль и независимо тестирует чужой. Автор
передаёт код и контракт, но не указывает место преднамеренной ошибки.
Тестировщик фиксирует дефект тестом и баг-репортом. Автор исправляет его
после получения отчёта; затем тестировщик повторно запускает все тесты.

## Общие договорённости

- Используем Python 3.12.x и `pytest`.
- В каждом модуле ровно пять функций и одна преднамеренная ошибка.
- Все функции возвращают значения, не печатая их. Внешние службы, файлы и
  интерфейсы не используем.
- Реализацию сверяем с контрактом соответствующего модуля в этом репозитории.
- Сохраняем переданную тестировщику версию, баг-репорт, исправление и выводы
  инструментов. Не удаляем историю и не скрываем провалившиеся тесты.
- Записываем только фактически выполненные проверки и результаты.
- Максим координирует сроки передачи, версии Python и сводный отчёт.

## Порядок действий для всех

1. Прочитать эту инструкцию, свой файл участника и контракт тестируемого модуля.
2. Установить Python 3.12.x и зависимости по `README.md`. Проверить, что команды
   pytest, покрытия и мутационного инструмента работают в общей среде.
3. Описать пять функций собственного модуля, затем реализовать их. Оставить
   ровно одну преднамеренную ошибку для независимого поиска тестировщиком.
4. Передать тестировщику свой исходный код и контракт. Зафиксировать версию
   Git (commit или ссылку на ветку).
5. Получить назначенный чужой модуль. Написать тесты обычных, граничных и
   ошибочных входных данных согласно контракту. Запустить их и покрытие.
6. На каждую обнаруженную ошибку завести баг-репорт в формате из
   `reports/coordination.md` и отправить автору модуля.
7. После исправления запустить полный набор тестов повторно. Подтвердить
   исправление или вернуть баг-репорт в работу с новым фактическим результатом.
8. Применить инструмент мутационного тестирования к исправленному модулю.
   Сохранить первый отчёт, изучить выживших мутантов, усилить тесты и повторить.
9. Передать Максиму свои материалы и отметить этапы в общей таблице.

## Контракты трёх остальных модулей

**Витя — строки:** `reverse_text(text)` переворачивает строку;
`count_vowels(text)` считает английские гласные a/e/i/o/u без учёта регистра;
`is_palindrome(text)` игнорирует регистр, но учитывает пробелы и знаки;
`count_words(text)` считает разделённые пробельными символами слова;
`remove_spaces(text)` удаляет обычные пробелы. Для пустой строки счётчики дают
0, палиндром — `True`, строковые преобразования — `""`.

**Артем — списки целых чисел:** `sum_numbers(numbers)` сумма;
`max_number(numbers)` максимум; `min_number(numbers)` минимум;
`count_even(numbers)` количество чётных; `reverse_numbers(numbers)` новый
обратный список. Для пустого списка сумма и количество чётных — 0, максимум и
минимум вызывают `ValueError`, обратный список — `[]`. Исходный список не менять.

**Катя — целые числа:** `is_even(n)` чётность; `is_positive(n)` строго больше
нуля; `is_multiple(n, k)` кратность, при `k == 0` — `ValueError`; `square(n)`
квадрат; `last_digit(n)` последняя цифра абсолютного значения (например,
`-123` даёт 3).
