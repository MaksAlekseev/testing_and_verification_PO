Мутационное тестирование list_tools.py

Версия модуля: main commit f8684c35e8020b7ef93ce1cc3bfa5a822018d22c.
Среда: Windows, Python 3.12.5, pytest 9.1.1, pytest-cov 7.1.0, pytest-gremlins 1.11.0.

Исходный запуск с 22 тестами:
python -m pytest tests/test_list_tools.py --gremlins --gremlin-targets=list_tools.py --gremlin-report=json
22 теста прошли. Инструмент создал 15 мутантов: 13 уничтожены, 2 выжили (87% уничтожено, 13% выжило).

Выжившие мутанты:
- В max_number сравнение > заменено на >=.
- В min_number сравнение < заменено на <=.

Обе замены меняют, какой из равных элементов выбирается при одинаковых экстремальных значениях, но числовой результат остаётся тем же. Контракт требует вернуть максимальное/минимальное значение и не задаёт, какой из равных элементов нужно выбрать. Поэтому эти два мутанта эквивалентны контракту и не могут быть убиты корректным тестом только по возвращаемому числу.

Для явной проверки повторяющихся экстремальных значений добавлены тесты:
test_max_number_handles_repeated_largest_values
test_min_number_handles_repeated_smallest_values

После добавления тестов полный набор прошёл: 106 passed. Повторный мутационный запуск с 24 тестами:
python -m pytest tests/test_list_tools.py --gremlins --gremlin-targets=list_tools.py --gremlin-report=json
24 теста прошли. Результат: 15 мутантов, 13 уничтожены, 2 эквивалентных выжили. Ошибок и таймаутов не было.

Первый и повторный машинные отчёты сохранены в gremlins_initial.json и gremlins_final.json. Результат относится к мутантам, которые генерирует pytest-gremlins 1.11.0.
